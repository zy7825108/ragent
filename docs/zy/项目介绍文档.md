# Ragent AI 项目介绍文档

## 1. 项目概述

Ragent AI 是一个企业级 RAG（检索增强生成）智能体平台，基于 Java 17 + Spring Boot 3 + React 18 构建。它覆盖了从文档入库到智能问答的全链路核心能力，包括多路检索、意图识别、问题重写、会话记忆、模型路由与容错、MCP 工具集成、链路追踪等。

### 项目定位
- 不是简单的 Demo 项目，而是完整的企业级 RAG 系统实现
- 覆盖 RAG 全链路工程问题的解决方案
- 提供生产级特性和完整的管理控制台
- 支持多模型供应商、多路检索、意图识别、工具调用等高级功能

## 2. 核心功能

### 2.1 智能问答功能
- **自然语言问答**：支持用户以自然语言提问，系统自动检索知识库并生成答案
- **深度思考模式**：提供更深入的分析和回答模式
- **示例问题引导**：首页提供示例问题标签，方便用户快速体验
- **Markdown 渲染**：支持答案的 Markdown 格式渲染，包括代码高亮、图片展示
- **回答评价**：用户可以对回答进行点赞/点踩评价

### 2.2 文档入库功能
- **多格式文档解析**：支持 PDF、Word、PPT、网页等多种格式文档解析
- **可编排入库流水线**：基于节点编排的 Pipeline，支持自定义入库流程
- **智能分块策略**：支持多种文档分块策略，包括语义分块、段落分块等
- **向量化处理**：使用 Embedding 模型将文档转换为向量存储到 Milvus 向量数据库
- **入库监控**：实时监控文档入库进度和状态

### 2.3 知识库管理
- **知识库创建与管理**：支持创建多个知识库，每个知识库独立管理
- **文档管理**：文档上传、删除、修改、查询
- **分块管理**：查看和管理文档分块信息
- **权限控制**：支持多租户和权限管理

### 2.4 意图识别与工具调用
- **树形意图体系**：支持领域→类目→话题的多级意图分类
- **歧义引导**：当意图识别置信度不足时，主动引导用户澄清
- **MCP 工具集成**：支持通过 MCP 协议集成业务工具
- **工具自动调用**：根据用户意图自动匹配并调用相应的业务工具

### 2.5 会话管理
- **会话记忆**：保留近 N 轮对话历史，支持自动摘要压缩
- **上下文理解**：多轮对话中自动补全上下文信息
- **会话持久化**：会话记录持久化到数据库，支持历史会话查询

### 2.6 模型管理
- **多模型支持**：支持百炼、SiliconFlow、Ollama、vLLM 等多种模型供应商
- **模型路由**：基于优先级的模型路由和容错机制
- **健康检查**：模型健康状态监控和自动熔断
- **首包探测**：模型切换时的首包探测机制，确保用户体验

### 2.7 系统监控与追踪
- **全链路追踪**：每个环节的耗时、输入输出、异常信息都有记录
- **链路可视化**：通过管理后台可视化查看完整的问答链路
- **系统监控**：实时监控系统运行状态和性能指标

## 4. 核心逻辑

### 4.1 智能问答流程

```
用户提问 → 问题重写 → 意图识别 → 多路检索 → 结果重排序 → 上下文组装 → 模型生成 → 流式输出
```

#### 4.1.1 问题重写
- 对用户原始问题进行优化和重写
- 补充上下文信息（多轮对话）
- 处理模糊问题，提高检索准确性

#### 4.1.2 意图识别
- 使用树形意图体系进行多级分类
- 计算意图识别置信度
- 置信度不足时，主动引导用户澄清

#### 4.1.3 多路检索
- **意图定向检索**：根据识别到的意图，在对应的知识库分区中检索
- **全局向量检索**：在整个知识库中进行向量检索
- **并行执行**：多个检索通道并行执行，提高响应速度

#### 4.1.4 结果重排序
- 对多个检索通道的结果进行去重
- 使用重排序算法优化结果顺序
- 基于相关性和置信度进行排序

#### 4.1.5 上下文组装
- 选择最优的检索结果作为上下文
- 组装成模型可接受的格式
- 控制上下文长度，避免 Token 超限

#### 4.1.6 模型生成
- 基于上下文和问题生成答案
- 支持流式输出，实时返回结果
- 模型路由和容错机制

### 4.2 文档入库流程

```
文档上传 → 格式解析 → 内容提取 → 智能分块 → 向量化处理 → 向量入库 → 元数据入库
```

#### 4.2.1 格式解析
- 使用 Apache Tika 解析多种格式文档
- 处理 PDF 中的表格、图片、双栏排版等复杂结构
- 提取干净的文本内容

#### 4.2.2 智能分块
- 支持多种分块策略
- 语义分块：基于自然语言处理技术，根据语义相关性分块
- 段落分块：按段落边界分块
- 固定大小分块：按固定字符数分块

#### 4.2.3 向量化处理
- 使用 Embedding 模型将文本转换为向量
- 支持多种 Embedding 模型
- 向量维度和模型配置可自定义

### 4.3 会话记忆管理

#### 4.3.1 滑动窗口机制
- 保留最近 N 轮对话
- 超限自动进行摘要压缩
- 平衡上下文完整性和 Token 成本

#### 4.3.2 摘要压缩
- 对历史对话进行智能摘要
- 保留关键信息，去除冗余内容
- 支持多轮对话的上下文理解

### 4.4 模型路由与容错

#### 4.4.1 模型路由策略
- 基于优先级的路由策略
- 支持模型权重配置
- 根据模型健康状态动态调整

#### 4.4.2 容错机制
- 三态熔断器（CLOSED → OPEN → HALF_OPEN）
- 失败次数达到阈值自动熔断
- 冷却期后进行探测请求
- 自动降级到下一个候选模型

#### 4.4.3 首包探测
- 模型切换时的首包探测机制
- 缓冲所有事件，确保用户端不会收到半截的脏数据
- 探测成功后正常输出，失败则切换到下一个模型

### 6.3 关键设计模式

| 设计模式 | 应用场景 | 解决的问题 |
|---------|----------|-----------|
| 策略模式 | SearchChannel、PostProcessor、MCPToolExecutor | 检索通道、后处理器、MCP 工具可插拔替换 |
| 工厂模式 | IntentTreeFactory、StreamCallbackFactory | 复杂对象的创建逻辑集中管理 |
| 注册表模式 | MCPToolRegistry、IntentNodeRegistry | 组件自动发现与注册，新增工具零配置 |
| 模板方法 | IngestionNode 基类 | 入库节点统一执行流程，子类只关注核心逻辑 |
| 装饰器模式 | ProbeBufferingCallback | 在不修改原有回调的前提下增加首包探测能力 |
| 责任链模式 | 后处理器链、模型降级链 | 多个处理步骤按顺序串联，灵活组合 |
| 观察者模式 | StreamCallback | 流式事件的异步通知 |
| AOP | @RagTraceNode、@ChatRateLimit | 链路追踪和限流逻辑与业务代码解耦 |

## 8. 项目特色与优势

### 8.1 企业级特性
- **限流**：支持全局并发限制和用户级限流
- **熔断**：模型健康检查 + 失败计数，自动熔断不可用的模型
- **可观测性**：全链路 Trace，每个环节的耗时、输入输出、异常信息都有记录
- **流式输出**：SSE 实时推送，首包探测机制保证模型切换时用户无感知
- **会话管理**：记忆压缩、摘要持久化、TTL 过期
- **认证鉴权**：基于 Sa-Token 的用户认证体系

### 8.2 可扩展性
- 新增检索通道：实现 `SearchChannel` 接口，注册为 Spring Bean，自动生效
- 新增后处理器：实现 `SearchResultPostProcessor` 接口，自动加入处理链
- 新增 MCP 工具：实现 `MCPToolExecutor` 接口，自动被 `DefaultMCPToolRegistry` 发现
- 新增入库节点：实现 `IngestionNode` 接口，可插入 Pipeline 任意位置
- 新增模型供应商：在 `infra-ai` 层实现 `ChatClient` 接口，配置候选列表即可参与路由

### 8.3 工程规范
- **分层架构**：framework / infra-ai / bootstrap 三层职责清晰
- **8 个专用线程池 + TTL 透传**：按工作负载特征配置了 8 个独立线程池
- **三态熔断器**：实现了经典的三态熔断器，每个模型独立维护健康状态
- **队列式并发限流**：基于 Redis 信号 + 有序集合 + Pub/Sub 通知实现分布式排队限流

## 9. 总结

Ragent AI 是一个功能完整、架构清晰、工程规范的企业级 RAG 智能体平台。它覆盖了从文档入库到智能问答的全链路核心能力，提供了生产级特性和完整的管理控制台。

该项目不是一个简单的 Demo，而是一个经过工程化设计的完整系统，解决了企业级 RAG 应用中的各种实际问题，包括文档解析、分块策略、多路检索、意图识别、问题重写、会话记忆、模型容错、MCP 工具调用、链路追踪等。
