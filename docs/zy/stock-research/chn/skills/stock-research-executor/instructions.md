# 股票研究执行器 - 操作指南

## 目的

本文档为执行8阶段投资尽调流程提供详细操作指南，是核心 SKILL.md 的扩展，包含具体指导、工作流程和最佳实践。

## 前提条件

使用本技能前，你应具备：

1. **来自 `stock-question-refiner` 的结构化研究提示词**
   - 包含：股票代码、投资风格、时间期限、研究范围、输出要求
   - 如缺失，先调用 `stock-question-refiner`

2. **对约束条件的清晰理解**
   - 投资参数（风格、风险容忍度、优先级）
   - 要使用（和避免）的数据来源
   - 输出格式和结构

3. **使用所需工具的权限**
   - Task（部署研究智能体）
   - WebSearch、WebFetch（研究）
   - Read、Write（生成报告）
   - TodoWrite（跟踪进度）

## 步骤1：验证并理解结构化提示词

### 检查清单：提示词完整性

继续之前，验证结构化提示词包含：

**基本信息**：
- [ ] 股票代码（例如 600519.SH、NVDA、03333.HK）
- [ ] 公司全称
- [ ] 市场（A股 / 港股 / 美股）

**投资参数**：
- [ ] 投资风格（价值/成长/困境反转/红利）
- [ ] 持有周期（短期/中期/长期）
- [ ] 风险容忍度（保守/平衡/激进）

**研究范围**：
- [ ] 列出所有8个阶段
- [ ] 标识出优先阶段（2-3个阶段做深度分析）
- [ ] 标注可以简化的阶段

**输出要求**：
- [ ] 指定报告格式（执行摘要、完整报告、表格）
- [ ] 指定估值方法
- [ ] 标注特殊要求（语言、时间范围、地理范围）

**研究约束**：
- [ ] 数据来源已排序优先级
- [ ] 列出强制验证要求
- [ ] "禁止事项"部分明确

### 如不完整：向用户提问

不要做假设。提出针对性问题：

```
我收到了您的研究请求，但我需要就[具体缺失项]进行澄清。

例如：
- "您提到了价值投资，但没有指定哪些阶段最重要。
  我是否应该优先关注生意质量、治理和估值？"
- "您没有指定时间范围。我应该分析过去3年、5年还是10年？"

请澄清以便我能适当定制研究。
```

### 如完整：进入规划

确认收到并总结理解：

```
我已收到您的结构化研究请求。让我确认我的理解：

**目标**: [代码] [公司名称]
**方法**: [投资风格]，[持有周期]，[风险容忍度]
**优先阶段**: [列出优先阶段]
**输出**: [描述报告结构]

我现在将创建详细的研究执行计划，请稍候...
```

## 步骤2：创建研究执行计划

### 向用户展示计划

展示计划并等待批准（除非在自动化模式下）：

```
我已为[公司]（[代码]）创建了研究执行计划。

**关键要点**：
- [数量]个阶段，部署约[总数]个研究智能体并行执行
- 优先关注：[列出优先阶段]
- 预期输出：标准化目录结构中的[数量]个文件
- 预估时间：[时间范围]

您希望我继续执行吗？或者您想调整计划？
```

**如用户要求调整**：相应修改计划
**如用户批准**：开始执行
**如无响应（自动化模式）**：短暂暂停后继续

## 步骤3：部署多智能体研究

### 关键规则：始终并行启动智能体

**❌ 错误（顺序启动）**：
```
启动智能体1A...
[等待完成]
启动智能体1B...
[等待完成]
```

**✅ 正确（并行启动）**：
```
为阶段1并行启动4个智能体...

[智能体1A] 研究公司事实底座 - 产品
[智能体1B] 研究公司事实底座 - 收入
[智能体1C] 研究公司事实底座 - 客户
[智能体1D] 研究公司事实底座 - 战略

[所有智能体现在同时运行]
```

### 如何启动并行智能体

使用**单条消息中多次调用Task工具**：

```python
# 伪代码示例（实际使用Task工具实现）

response = [
    Task(agent_1a_task),
    Task(agent_1b_task),
    Task(agent_1c_task),
    Task(agent_1d_task)
]

# 4个智能体立即启动并并行运行
# 等待全部完成后收集结果
```

### 收集智能体结果

智能体完成后：

**1. 汇编所有发现**：
```
阶段[X]智能体结果摘要：

**智能体XA**: [关键发现的2句话摘要]
**智能体XB**: [关键发现的2句话摘要]
**智能体XC**: [关键发现的2句话摘要]
**智能体XD**: [关键发现的2句话摘要]
```

**2. 识别重叠和冗余**：
```
**共识发现**（2个以上智能体提及）：
- [发现1]
- [发现2]

**独特发现**（仅来自单个智能体）：
- [仅来自智能体XB的发现]
- [仅来自智能体XC的发现]
```

**3. 解决矛盾**：
```
**发现的矛盾**：
- 问题：[智能体XA说Y，智能体XB说Z]
- 解决：[审查来源，确定哪个更可信，
  或呈现两种观点]
```

**4. 创建连贯叙事**：
```
**综合**：将发现整合为逻辑流：
- 从最重要/共识发现开始
- 解决独特洞察
- 承认矛盾并解释
- 突出不确定性和空白
```

## 步骤4：质量保证

### 引用验证

完成一个阶段的研究后，执行引用检查：

**使用citation-validator技能**：
```
请验证[文件路径]中的引用。

检查：
- 完整性（作者、日期、标题、URL）
- 格式一致性
- 来源质量评级
- 缺失的引用
- 矛盾的声明

在需要的地方提供修正建议。
```

### 交叉验证检查

**1. 利润 vs 现金流**：
```markdown
## 现金流质量分析

**经营现金流/净利润**：
| 年份 | 净利润 | OCF | OCF/NI比率 |
|------|--------|-----|-----------|
| 2023 | [金额] | [金额] | [比率] |
| 2022 | [金额] | [金额] | [比率] |
| 2021 | [金额] | [金额] | [比率] |

**评估**：
- [ ] 比率 > 1.0：优秀（现金超过盈利）
- [ ] 比率 0.8-1.0：良好（现金大致匹配盈利）
- [ ] 比率 0.5-0.8：值得关注（显著应计利润）
- [ ] 比率 < 0.5：红旗（盈利未转化为现金）
```

**2. 公司 vs 同行**：
```markdown
## 同行对比

**关键比率对比**：
| 指标 | [公司] | [同行1] | [同行2] | [同行3] |
|------|--------|---------|---------|---------|
| P/E (TTM) | [值] | [值] | [值] | [值] |
| P/B | [值] | [值] | [值] | [值] |
| ROE | [值] | [值] | [值] | [值] |
| 净利率 | [值] | [值] | [值] | [值] |
| 营收增速 | [值] | [值] | [值] | [值] |

**评估**：
- [公司]在[指标]上[低于/高于/等于]同行平均
- 这[合理/不合理]因为：[解释]
```

**3. 空头分析**：
```markdown
## 空头情景

**识别的关键风险**：

1. **[风险1]**: [描述]
   - 可能性：[高/中/低]
   - 影响：[高/中/低]
   - 触发事件：[什么会导致此风险]
   - 缓解：[公司如何避免]

2. **[风险2]**: [描述]
   - ...
```

### 完整性审查

最终综合前，确保：

**内容完整性**：
- [ ] 所有8个阶段已覆盖
- [ ] 用户优先阶段获得额外深度
- [ ] 执行摘要综合了所有发现
- [ ] 红旗和风险已识别
- [ ] 多空观点均已呈现

**结构完整性**：
- [ ] 所有必需文件已创建
- [ ] 目录结构匹配模板
- [ ] README.md提供导航
- [ ] sources/bibliography.md完整

**质量完整性**：
- [ ] 无"[待填写]"等占位符
- [ ] 无无支持的模糊陈述
- [ ] 无未解决的矛盾
- [ ] 无未解释的"未知"标注

## 特殊场景

### 场景1：困境公司（例如破产风险）

**调整**：
- 强调阶段4（偿付能力）和阶段7（清算价值）
- 添加："持续经营 vs 清算"分析
- 估值：关注恢复情景、概率加权预期价值
- 风险分析：强调二元结果和时间风险

### 场景2：高增长公司（未盈利）

**调整**：
- 阶段4：关注现金消耗率、存续期、盈利路径
- 估值：使用用户价值模型、TAM渗透率、增长优先于盈利
- 跳过：传统P/E、DCF（如无当前现金流）
- 添加：增长可持续性评估、竞争护城河持久性

### 场景3：新上市公司（IPO）

**调整**：
- 阶段1：强调IPO招股说明书分析
- 阶段4：历史数据有限（使用招股说明书财务数据）
- 阶段5：检查锁定期到期、内部人减持计划
- 估值：困难（无交易历史），关注招股说明书指引

### 场景4：外国公司（例如中国A股）

**调整**：
- 数据来源：强调当地语言来源（A股用中文）
- 翻译：提供双语或说明是否使用英文来源
- 监管：包含特定国家的监管风险
- 会计：注明是否使用IFRS、GAAP或当地准则（中国用CAS）

## 最佳实践

### 1. 保持客观

**要做**：
- 呈现均衡事实
- 承认不确定性
- 空头和多头观点并列呈现

**不要做**：
- 使用炒作语言（"不可思议的机会"、"必买"）
- 使用恐慌语言（"即将崩溃的灾难"）
- 选择性呈现数据支持某个叙事

### 2. 优先使用一手来源

**来源层级**：
1. 公司文件（年报、监管提交）
2. 监管文件
3. 公司直接沟通
4. 知名第三方研究（保持怀疑态度）
5. 新闻和二手分析（核实声明）

### 3. 对局限性保持透明

当你找不到信息时：
```markdown
**局限性**: [无法确定的内容]
- [为什么无法确定（例如未披露、来源矛盾）]
- [这对分析意味着什么]
- [需要什么额外研究]
```

### 4. 使用TodoWrite跟踪进度

跟踪你的研究进度：

```python
TodoWrite([
    {"content": "阶段1: 公司事实底座", "status": "completed"},
    {"content": "阶段2: 行业分析", "status": "in_progress"},
    {"content": "阶段3-7: 待处理", "status": "pending"}
])
```

这有助于用户查看进度，并在中断时允许恢复。

## 疑难解答

### 问题：智能体返回矛盾的发现

**解决方案**：
1. 审查每个矛盾声明的来源
2. 评估来源质量（A-E级）
3. 检查发布日期（旧信息可能已过时）
4. 带来源归属呈现两种观点
5. 解释矛盾的可能原因

### 问题：无法找到信息

**解决方案**：
1. 尝试替代搜索查询
2. 用不同语言搜索（如果是外国公司）
3. 从监管文件而非新闻中寻找
4. 在报告中明确承认局限性
5. 标记供用户进一步调查

### 问题：WebSearch返回糟糕的结果

**解决方案**：
1. 使用更具体、有针对性的查询
2. 添加 site: 过滤（例如 "site:sec.gov"、"site:cninfo.com.cn"）
3. 使用文件类型过滤（例如 "filetype:pdf 年度报告"）
4. 尝试替代搜索词
5. 检查公司是否更名或更改代码

### 问题：信息过载（来源太多）

**解决方案**：
1. 优先使用权威来源（年报、监管文件）
2. 除非需要历史背景，限制分析至最近3-5年
3. 聚焦重要信息（忽略琐碎细节）
4. 跨来源综合而非罗列所有
