---
description: PG - PRD 澄清合并命令 - 将澄清答案合并入 PRD，自动读取已保存文件，无需重复粘贴 (PG Clarification Merge Command)
---

当用户输入 `/pg_clarify` 命令时，你必须严格按照以下步骤执行：

---

## 第一步：解析用户输入

### 1.1 澄清答案块
从用户输入的正文中提取澄清答案，通常以下格式：
- `Q数字 - 问题描述：答案`
- 或自由文本形式的澄清说明

### 1.2 原始 PRD（优先自动读取文件）

**优先方式（自动读取已保存文件）：**
1. 读取 `spec-status.json`，获取 `files.prd` 指向的文件路径
2. 若文件存在，直接读取该文件内容作为原始 PRD，无需用户重新粘贴

**降级方式（手动粘贴）：**
若 `spec-status.json` 不存在或 PRD 文件找不到，识别用户输入中的以下标记：
- `===原始 PRD===` 与 `===PRD 结束===`
- 或 `===PRD 开始===` 与 `===PRD 结束===`

**⚠️ 两种方式都失败时，输出提示并等待：**
```
⚠️ 无法读取原始 PRD，请提供（任选一种）：

1. 先执行 `/pg_prd` 生成并保存 PRD 文件
2. 或手动粘贴原始 PRD：

/pg_clarify
[澄清答案]

===原始 PRD===
[PRD 全文]
===PRD 结束===
```

---

## 第二步：分析澄清内容对 PRD 的影响

| 澄清类型 | 通常影响的 PRD 章节 |
|---|---|
| 功能交互方式 | 第 4 章"详细功能描述" |
| 业务规则 | 第 4 章 + 第 7 章"异常与容错处理" |
| 数据字段 | 第 6 章"数据结构与字段说明" |
| 边界条件 | 第 5 章"边界与限制" |
| 验收标准 | 第 8 章"验收标准" |
| 主流程变化 | 第 10 章 Mermaid 流程图 |

---

## 第三步：执行合并更新

1. **直接融入**：将答案整合到对应章节，不新增独立"Q&A"章节
2. **同步流程图**：若澄清涉及流程变化，必须更新第 10 章 Mermaid 图
3. **删除已解答问题**：从第 9 章删除所有被本次答案解决的条目
4. **无答案问题也删除**：未提供答案的问题也一并移除
5. **保留所有章节**：即使内容为空也写"暂无"

---

## 第四步：输出完整更新后的 PRD 并写回文件

在 PRD 开头加更新标记：
```
> 📝 更新记录：已于 [当前日期] 合并澄清答案，共处理 [N] 条。
```

输出完整 PRD 后，将新版本写入文件：
- 新文件名规则：同日追加 `_v2`；新日期用新日期
- 更新 `spec-status.json` 的 `files.prd` 指向新文件
- 更新 `currentPhase` 为 `"澄清中"`

---

## 第五步：确认后续行动

```
✅ PRD 已更新并自动保存至：[文件路径]
已合并 [N] 条澄清内容。

→ 如需继续修改 PRD：直接告诉我，或使用 `/pg_edit [描述]`
→ 如 PRD 已确认无误：`/pg_plan [补充说明或已有系统设计文档]`
```

**状态栏：**
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 需求：[需求名称]
📍 当前阶段：澄清中
⏭  下一步：/pg_plan 生成程序设计文档
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

---

## 注意事项

1. **不新增独立章节**：澄清答案必须融入对应章节
2. **流程图同步**：只要涉及流程变化，必须更新 Mermaid 图
3. **完整输出**：必须输出完整 PRD，不得以"…不变…"省略任何部分
4. **保持一致性**：更新后各章节之间描述必须逻辑一致
