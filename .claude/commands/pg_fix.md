description: PG - 修改代码命令 - 针对已有代码进行局部修改（Bug修复/需求变更），输出修改方案等待确认后执行 (PG Code Fix Command)
---

当用户输入 `/pg_fix` 命令时，你必须严格按照以下步骤执行：

---

## 修改代码规范（内嵌）

- **先方案后执行**：任何修改在执行前必须输出方案预览，等待用户确认
- **范围最小化**：只修改受影响的文件，不做无关改动
- **中文注释**：修改时维护/补充中文注释，不得引入英文注释
- **完整输出**：修改后输出完整文件代码（或清晰的 diff）

---

## 执行步骤

### 第一步：解析修改意图

从用户描述中提取：
- **问题类型**：Bug修复 / 需求变更 / 代码优化 / 文档同步驱动
- **定位**：结合设计文档推断受影响的文件和方法
- **影响范围**：估算涉及的文件数量

**若描述过于模糊，先询问：**
```
请描述需要修改的内容：
- 是什么问题？（Bug / 需求变更 / 优化）
- 大概在哪个文件或功能模块？（选填，我会帮您定位）
```

### 第二步：输出修改方案（必须先展示，再执行）

```
📝 代码修改方案确认

【问题描述】：[用户描述]
【问题类型】：[Bug修复 / 需求变更 / 优化]

【受影响文件】：
  1. XxxService（后端）/ XxxView.vue（前端）— 修改 doSomething() 方法/函数，补充返回字段
  2. XxxVO（后端）/ api/xxx.js（前端）— 新增字段定义

【修改范围说明】：
  仅修改以上 2 个文件，不涉及其他文件。

是否确认按此方案执行？（确认 / 取消 / 我要补充）
```

### 第三步：执行修改

用户确认后，优先使用 diff 格式展示修改点：

```diff
// XxxService.java - doSomething() 方法
- return new PageResult<>(items);
+ PageResult<XxxVO> result = new PageResult<>(items);
+ result.setTotal(total); // 补充返回总数，解决分页统计缺失问题
+ return result;
```

### 第四步：判断是否需要同步文档

| 修改类型 | 是否需要同步文档 |
|---|---|
| 接口路径/参数/响应字段变更 | ✅ 提示 `/pg_edit` 同步设计文档 |
| 核心业务逻辑变更 | ✅ 提示 `/pg_edit` 同步时序图/流程描述 |
| 纯 Bug 修复（无接口/逻辑变化） | ⬜ 无需同步 |
| 配置项变更 | ✅ 提示 `/pg_edit` 同步配置清单（后端：Apollo 配置清单；前端：环境变量/配置文件） |

**需要同步时输出：**
```
⚠️ 文档同步建议：
→ `/pg_edit 更新程序设计文档第X章[具体内容]`
```

### 第五步：建议下一步

```
✅ 代码修改完成！

→ 如需同步文档：`/pg_edit [描述]`
→ 如需验证整体实现：`/pg_verify`
→ 如还有其他修改：`/pg_fix [描述]`
→ 如一切就绪准备收尾：`/pg_done`
```

---

## `/pg_fix` 与 `/pg_code` 的区别

| | `/pg_code` | `/pg_fix` |
|---|---|---|
| 定位 | 从零按任务清单产码 | 对已有代码局部修改 |
| 驱动方式 | 任务清单（task.md）驱动 | 问题描述驱动 |
| 前置要求 | 必须有设计文档 | 无强制前置要求 |

---

## 禁止行为

- ❌ 禁止在未获得用户确认的情况下修改任何文件
- ❌ 禁止修改设计文档范围外且用户未提及的文件
- ❌ 禁止英文注释
- ❌ 禁止自动执行 `git commit`
