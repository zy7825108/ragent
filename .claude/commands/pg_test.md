---
description: PG - 测试用例生成命令 - 基于 PRD 验收标准和接口设计自动生成功能/边界/异常三类测试用例，可导出给 QA (PG Test Case Generation Command)
---

当用户输入 `/pg_test` 命令时，你必须严格按照以下步骤执行：

---

## 第一步：加载测试基准文档

1. **读取 PRD 文档**：从 `spec-status.json` 中获取 `files.prd` 路径，读取第 8 章"验收标准"
2. **读取程序设计文档**：读取第 5 章"API 接口设计"和第 6 章"服务层核心逻辑"
3. **读取边界条件**：PRD 第 5 章"边界与限制"

**若无 spec-status.json（上下文自愈）：**
```
未找到 spec-status.json，请提供测试基准（任选一种）：
1. PRD 文档路径（或粘贴 PRD 内容）
2. 直接描述需要测试的功能（我将基于描述生成测试用例）
```

---

## 第二步：分析与生成三类测试用例

### 类型 A：功能测试用例（Happy Path）
覆盖 PRD 第 8 章验收标准中的**正向场景**：
- 每个功能点的标准使用流程
- 关键数据的正确存储与返回
- 状态流转的正确性

### 类型 B：边界测试用例（Boundary）
基于 PRD 第 5 章边界条件和接口入参：
- 字符串：空字符串、最大长度边界、特殊字符
- 数值：0、负数、最大值、超出范围值
- 列表：空列表、单个元素、最大数量元素
- 时间：过去时间、未来时间、边界时间点
- 权限：无权限用户、越权访问

### 类型 C：异常测试用例（Exception Path）
基于 PRD 第 7 章异常与容错处理：
- 必填参数缺失
- 参数类型错误
- 数据不存在（ID 不存在）
- 并发冲突（如幂等测试）
- 依赖服务超时/失败

---

严格按照以下格式输出：

```markdown

> 生成时间：[当前日期]
> 基准文档：[PRD 路径 / 程序设计文档路径]
> 测试范围：[功能模块描述]

---
```

## 第四步：持久化测试用例文档并引导

1. 将测试用例文档写入 `测试用例_[需求名称]_YYYYMMDD.md`
2. 更新 `spec-status.json`，添加 `files.testcase` 字段
3. 引导下一步：

```
✅ 测试用例已生成并保存至：[文件路径]

共生成 [N] 个测试用例：
  🔴 P0（必须通过）：[N] 个
  🟡 P1（建议通过）：[N] 个
  🟢 P2（可选）：[N] 个

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 需求：[需求名称]
📍 当前阶段：测试中
⏭  建议下一步：
  → 将测试用例文件交给 QA 执行
  → 执行完成后 `/pg_verify` 进行开发侧整体验证
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 特殊场景

### 仅生成冒烟用例（快速提测）：
```
/pg_test --smoke    → 只生成 P0 级别用例（功能主路径 + 关键异常）
```

### 生成自动化测试框架代码（实验性）：
```
/pg_test --auto     → 在用例之后生成对应的接口测试脚本骨架（pytest / JUnit 格式）
```
