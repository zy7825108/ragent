---
description: PG - 需求收尾命令 - 汇总所有产物、生成稳定性 Checklist、标记需求完成 (PG Done Command)
---

当用户输入 `/pg:done` 命令时，你必须严格按照以下步骤执行：

> ⚠️ 本命令会生成实体文件，**文件生成后必须立即写入磁盘**，不得仅在回复中展示而不写文件。

---

## 第一步：前置检查

读取 `spec-status.json`，检查以下条件：

| 条件 | 状态 | 处理方式 |
|---|---|---|
| `files.prd` 不为空 | ✅/❌ | ❌ 停止，提示先执行 `/pg:prd` |
| `files.design` 不为空 | ✅/❌ | ❌ 停止，提示先执行 `/pg:plan` |
| `task.md` 中无 `[ ]` 未完成项 | ✅/⚠️ | ⚠️ 列出未完成项，询问是否继续 |
| 最近执行过 `/pg:verify` 且无 ❌ | ✅/⚠️ | ⚠️ 提醒但不强制阻止，询问确认 |

**若 task.md 中仍有未完成任务，输出（Markdown 格式，非代码块）：**

⚠️ task.md 中仍有 [N] 个未完成子任务：
- [ ] XxxService.java 产码
- [ ] ApolloConfig.java 修改

请选择：
→ 回复「继续」— 忽略未完成项，强制收尾
→ 回复「取消」— 先完成剩余任务

---

## 第二步：生成并写入收尾报告

> ⚡ **立即写文件**：生成 `收尾报告_[需求名称]_YYYYMMDD.md`，写入 `[specDir]` 目录。

报告内容（Markdown 格式）：

```markdown
# [需求名称] 收尾报告

> 生成时间：YYYY-MM-DD HH:mm
> 需求归档目录：[specDir]

## 产物汇总

| 产物类型 | 文件名 | 最后更新 |
|---|---|---|
| PRD 文档 | [files.prd] | [updatedAt] |
| 程序设计文档 | [files.design] | [updatedAt] |
| 澄清记录 | [files.clarify 或「无」] | — |
| 任务清单 | [files.task] | — |
| 稳定性 Checklist | [files.checklist] | — |

## 变更摘要

[基于 task.md 中已完成项目，一句话描述本次需求的核心变更]

## 涉及文件清单

[从程序设计文档第 2 章复制完整文件清单]
```

写入完成后立即告知：
> ✅ 收尾报告已写入：`[文件路径]`

同时更新 `spec-status.json`：
- `files.report` → 指向收尾报告文件
- `updatedAt` → 当前时间

---

## 第三步：检查文档与代码同步状态

快速检查代码实现与程序设计文档的一致性：
- 若有未同步内容，明确指出并提示：「建议先执行 `/pg:edit` 同步后再完成收尾」
- 若完全同步，继续下一步

---

## 第四步：生成并写入稳定性上线 Checklist

> ⚡ **立即写文件**：生成 `上线Checklist_[需求名称]_YYYYMMDD.md`，写入 `[specDir]` 目录。

**根据本次需求实际涉及的模块动态生成，只输出涉及的章节，不输出无关章节。**

文件内容（Markdown 格式）：

```markdown
# [需求名称] 稳定性上线 Checklist

> 生成时间：YYYY-MM-DD HH:mm
> **上线前请逐项确认，完成后在 [ ] 中打 ✅**

---

## 一、代码稳定性

- [ ] Code Review 已完成（`/pg:review` 无 🔴 必须修复项）
- [ ] 代码验证已通过（`/pg:verify` 无 ❌ 不符合项）
- [ ] 所有公共方法有中文 Javadoc 注释
- [ ] 无硬编码的魔法值（已提取为常量或配置）
- [ ] 边界条件已处理（null 值、空列表、越界等）
- [ ] 异常均有明确的捕获和处理逻辑，无裸 catch(Exception e) {}

## 二、数据稳定性

[仅当本次需求有数据库变更时输出]

- [ ] DDL 脚本（建表/加字段/加索引）已在**测试环境**执行并验证
- [ ] 新增字段有合理默认值（存量数据不受影响）
- [ ] 数据迁移脚本已准备并在测试环境验证
- [ ] **回滚 SQL 已准备**（知道出问题怎么还原数据）
- [ ] 大表 DDL 操作已评估锁表风险（如需 gh-ost / pt-osc 执行）
- [ ] 索引已根据实际查询场景设计（非全量冗余索引）

## 三、接口稳定性

[仅当本次需求有接口变更或新增时输出]

- [ ] 新增接口已做入参校验（@NotNull / @Valid 等）
- [ ] 修改接口向后兼容（未删除/改名历史字段）
- [ ] 接口响应错误码统一（使用项目规范的 BizException）
- [ ] 若接口有破坏性变更：已通知所有调用方并确认联调通过
- [ ] 接口文档（YAPI/Swagger）已同步更新

## 四、配置稳定性

[仅当本次需求有 Apollo 配置项变更时输出]

- [ ] 新增 Apollo 配置项已在**测试环境**验证生效
- [ ] 配置项有合理默认值（服务启动不依赖配置是否推送）
- [ ] 灰度配置项的灰度顺序和范围已明确（先内部 → 金丝雀 → 全量）
- [ ] 配置项的影响范围已确认（避免跨业务误触）
- [ ] 紧急关闭开关已就位（出问题可关闭功能）

## 五、并发与事务稳定性

[仅当本次需求涉及并发写或事务操作时输出]

- [ ] 核心写操作已实现幂等（requestId / 唯一键 / 状态判断）
- [ ] 事务边界已明确（@Transactional 的范围最小化，避免大事务）
- [ ] 分布式锁/乐观锁已在并发场景正确使用
- [ ] 锁粒度合理（避免全表锁或过粗粒度锁）
- [ ] 并发测试场景已覆盖（多线程下数据一致性验证）

## 六、缓存稳定性

[仅当本次需求涉及缓存读写时输出]

- [ ] 缓存 Key 设计合理（无冲突，含版本号或 namespace）
- [ ] 缓存更新策略明确（先更新 DB 再删缓存 / 先删缓存再更新 DB）
- [ ] 缓存穿透防护已就位（null 值缓存 / 布隆过滤器）
- [ ] 缓存雪崩防护已就位（过期时间随机抖动）
- [ ] 缓存与 DB 数据一致性已验证

## 七、消息队列稳定性

[仅当本次需求涉及 MQ 生产或消费时输出]

- [ ] 消息消费已实现幂等（消费多次结果一致）
- [ ] 消费失败已配置重试策略（最大重试次数 / 死信队列）
- [ ] 消息生产失败有兜底处理（事务消息 / 本地消息表）
- [ ] 消息体字段变更向后兼容（消费方可处理旧格式）
- [ ] 消费 TPS 已评估，不超过下游服务承载能力

## 八、监控与应急

- [ ] 关键业务指标已有监控（如：下单量、转化率、成功率）
- [ ] 关键技术指标已有监控（接口 P99 响应时间、错误率、JVM GC）
- [ ] 告警规则已配置（异常触发时及时通知）
- [ ] **回滚方案已明确**（Apollo 开关关闭 / 代码回滚 / 数据回滚步骤）
- [ ] 上线后 30 分钟拨测计划已就绪（关键接口 + 核心链路）

## 九、上线后验证（上线后 30 分钟内执行）

- [ ] 拨测关键接口，返回结果符合预期
- [ ] 查看错误日志，无新增异常（对比上线前基线）
- [ ] 核心功能 P0 用例快速回归（手工或自动化）
- [ ] 监控大盘无异常波动（成功率/响应时间/错误率）
- [ ] 若有灰度：确认灰度流量功能表现符合预期后再扩量
```

写入完成后在回复中展示完整内容并告知：
> ✅ 稳定性 Checklist 已写入：`[文件路径]`

---

## 第五步：在回复中展示 Commit Message（不写文件）

直接在回复中输出，供用户复制后手动执行 `git commit`：

---

📝 **建议的 Commit Message**（确认后手动执行 `git commit`）：

```
feat: [需求名称] - [一句话核心功能描述]（中文）

变更内容：
- 新增 XxxController，处理 xxx 请求
- 新增 XxxService，实现 xxx 核心业务逻辑
- 修改 ApolloConfig，新增 xxx.enable 配置项
- 新增数据库字段 source_type（tinyint，标识来源平台）

关联需求：[PRD 文档路径]
设计文档：[程序设计文档路径]
```

> ⚠️ **禁止自动执行 `git commit`**，请用户确认内容后手动提交。

---

## 第六步：更新状态并输出完成报告

**立即**更新 `spec-status.json`：
- `currentPhase` → `"已完成"`
- `files.checklist` → 上线 Checklist 路径
- `updatedAt` → 当前时间

在回复中输出完成报告（Markdown 格式，非代码块）：

---

🎉 **需求已完成收尾！**

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 需求：[requirementName]
📍 状态：✅ 已完成
📁 归档目录：[specDir]
🕐 完成时间：[当前时间]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📦 **本次产物文件**：
- 📄 `[PRD 文件路径]`
- 📐 `[程序设计文档路径]`
- 📋 `[收尾报告路径]`
- ✅ `[稳定性 Checklist 路径]`

**下一步操作**：
→ 按 Checklist 逐项确认后执行上线
→ 复制上方 Commit Message，手动执行 `git commit`
→ `/pg:archive` 归档所有产物到 `pg/doc/archive/`

---

## 禁止行为

- ❌ 禁止只在回复中展示而不写文件（收尾报告和 Checklist 必须写入实体文件）
- ❌ **禁止将 Commit Message 写入文件**（只在回复中展示）
- ❌ 禁止自动执行 `git commit`
- ❌ 当存在 `/pg:verify` ❌ 不符合项时，禁止允许收尾
- ❌ Checklist 中与本次需求无关的章节**必须省略**，不得全量输出
