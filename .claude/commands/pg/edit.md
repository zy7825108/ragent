---
description: PG - 修改文档命令 - 修改 PRD 或程序设计文档指定内容，自动版本管理并归档新版本 (PG Document Edit Command)
---

当用户输入 `/pg:edit` 命令时，你必须严格按照以下步骤执行：

---

## 文档编辑规范（内嵌）

- **保留结构**：修改时必须保留所有章节，不得删除任何章节标题
- **版本可追溯**：每次修改自动更新文档头部的版本和更新记录
- **范围最小化**：只修改用户指定的内容，不对无关章节做格式调整
- **完整输出**：始终输出完整修改后的文档，不得以"…不变…"省略

---

## 执行步骤

### 第一步：识别目标文档和修改意图

| 关键词 | 目标文档 |
|---|---|
| PRD、需求文档 | PRD 文档 |
| 程序设计、设计文档、方案 | 程序设计文档 |
| 现状设计、遗留系统文档 | 现状程序设计文档 |
| 无法确定 | 询问用户 |

### 第二步：读取当前文档

1. 读取 `spec-status.json`，获取对应文档的最新文件路径
2. 若无状态文件，询问：
   ```
   请提供需要修改的文档（任选一种）：
   1. 文件路径
   2. 直接粘贴文档全文
   ```

### 第三步：输出修改预览（必须等待确认）

```
📝 文档修改预览

【目标文档】：[文档类型]（当前版本 v[x]）
【修改章节】：[章节编号和名称]
【内容变化】：
  原文：[原始内容片段]
  修改为：[修改后内容片段]

【关联影响】：
  - [如有其他章节或文档受影响，列出建议同步项]

是否确认？（确认 / 取消 / 调整）
```

### 第四步：执行修改并更新版本信息

在文档头部更新元信息：
```markdown
---
归档时间: YYYY-MM-DD HH:mm
文档类型: [类型]
版本: v[x+1]
更新记录:
  - v[x+1] ([今天]): [本次修改摘要]
  - v[x] ([上次]): [上次修改摘要]
---
```

### 第五步：写入新版本文件

- 新文件命名：同日追加 `_v2`；新日期用新日期
- 更新 `spec-status.json` 中对应文件字段指向最新版本

### 第六步：完成后输出

```
✅ 文档已更新至 v[新版本号]！

【文件路径】：[路径]
【修改摘要】：[描述]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 需求：[需求名称]
📍 当前阶段：[currentPhase]
⏭  建议下一步：[根据阶段建议]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

---

## 文档修改后的关联检查

修改完成后，自动检查是否影响其他文档：

| 修改类型 | 需要同步的地方 |
|---|---|
| 接口字段变更（PRD 第6章） | 程序设计文档第5章（API设计）|
| 业务流程变更（PRD 第4章） | PRD 第10章流程图、设计文档第7/8章 |
| 程序设计文档接口变更 | 代码中对应的 Controller/VO → `/pg:fix` |

**检测到需要同步时提示：**
```
⚠️ 关联同步提醒：
- [受影响内容] → `/pg:edit [具体修改描述]` 或 `/pg:fix [描述]`
```

---

## 禁止行为

- ❌ 禁止删除任何章节标题（即使内容为空也写"暂无"）
- ❌ 禁止以"…不变…"省略输出，必须完整文档
- ❌ 禁止覆盖历史版本文件（新版本存新文件）
- ❌ 禁止未确认直接写入文件
