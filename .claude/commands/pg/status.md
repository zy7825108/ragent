---
description: PG - 状态查询命令 - 查看当前需求执行到哪一步，展示完整进度、产物列表和断点恢复提示，用于会话恢复和流程继续 (PG Status Query Command)
---

当用户输入 `/pg:status` 命令时，你必须严格按照以下步骤执行：

---

## 第一步：查找状态文件

按优先级扫描 `spec-status.json`：
1. 当前项目 `pg/doc/` 目录下各需求子目录
2. `~/pg/doc/` 目录下各需求子目录
3. 当前目录（兜底）

**若找到多个**（多并行需求），列出所有并询问用户选择：
```
发现 [N] 个进行中的需求：
1. [需求名称A] — 当前阶段：[阶段] — 最后更新：[时间]
2. [需求名称B] — 当前阶段：[阶段] — 最后更新：[时间]

请输入序号选择要查看的需求：
```

---

## 第二步：输出完整状态面板

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 需求：[requirementName]
📍 当前阶段：[currentPhase]
📁 文件目录：[specDir]
🕐 最后更新：[updatedAt]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📂 当前产物：
  [遍历 files 字段]
  · PRD：[files.prd 或「未生成」]
  · 设计文档：[files.design 或「未生成」]
  · 澄清记录：[files.clarify 或「未生成」]
  · 任务清单：[files.task 或「未生成」]

🗺  工作流进度：

  ⬜/✅ /pg:analyze — 遗留系统梳理（老旧项目专用）
  ⬜/✅ /pg:prd     — 需求文档
  ⬜/✅ /pg:clarify — 需求澄清
  ⬜/✅ /pg:plan    — 程序设计文档
  ⬜/✅ /pg:task    — 任务拆分（含工时估算）
  ⬜/⏳ /pg:code    — 产码 [X/N 已完成]
  ⬜/✅ /pg:verify  — 开发自验
  ⬜/✅ /pg:done    — 收尾归档

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

进度图标说明：
- `✅` 已完成（files 中有对应文件，或 currentPhase 已过该阶段）
- `⏳` 进行中（currentPhase 当前阶段）
- `⬜` 未开始

---

## 第三步：给出恢复建议

根据 `currentPhase` 给出精确的恢复指引：

### 当前阶段 = 「待需求分析」
```
⏭  建议下一步：`/pg:prd [需求来源]` 开始生成需求文档
```

### 当前阶段 = 「PRD生成」
```
⏭  建议下一步：
   → `/pg:clarify [澄清答案]` 补充澄清
   → `/pg:plan` 直接进入技术设计
```

### 当前阶段 = 「澄清中」
```
⏭  建议下一步：`/pg:plan` 生成程序设计文档
```

### 当前阶段 = 「技术设计」
```
⏭  建议下一步：
   → `/pg:task` 拆分开发任务（推荐）
   → `/pg:code` 直接开始产码
```

### 当前阶段 = 「任务拆分」
```
⏭  建议下一步：`/pg:code` 开始按任务清单逐文件产码
```

### 当前阶段 = 「开发中」（有产码断点）
```
⏳ 产码进度：已完成 [X]/[N] 个文件
   已完成：[completedList]
   当前：[currentFile]

⏭  建议下一步：`/pg:code` 从断点继续产码
```

### 当前阶段 = 「验证中」
```
⏭  建议下一步：`/pg:verify` 对照设计文档验证代码实现
```

### 当前阶段 = 「已完成」
```
✅ 该需求已完成！

归档产物：[列出 files 中所有文件]

→ `/pg:archive` 按需归档产物
→ `/pg:spec [新需求名]` 开始新需求
```

---

## 第四步：若未找到状态文件

```
⚠️ 未在以下目录找到进行中的 PG Spec 工作流：
   · [项目根]/pg/doc/
   · ~/pg/doc/

可能的原因：
1. 尚未初始化需求 → `/pg:spec [需求名称]` 开始新需求
2. 文件已被移动或删除
3. 当前工作目录不在项目根目录下

→ `/pg:spec [需求名称]` 初始化新需求
→ `/pg:prd [需求来源]` 直接开始（会自动初始化）
```
