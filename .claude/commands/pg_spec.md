## PG Spec Workflow 命令体系

本工作流是一套完整的需求→设计→开发→归档闭环体系，所有命令均以 `/pg_` 为前缀。

### 完整命令索引

| 命令 | 阶段 | 说明 |
|---|---|---|
| `/pg_analyze` | 前置（老旧项目） | 梳理遗留系统架构，生成「现状程序设计文档」|
| `/pg_spec` | 总控 | 初始化新需求 / 查看当前阶段状态 |
| `/pg_status` | 状态查询 | 查看当前需求执行到哪一步，支持产码断点恢复 |
| `/pg_prd` | 需求分析 | 将需求来源转换为标准 PRD 文档，自动写入文件 |
| `/pg_clarify` | 需求澄清 | 将澄清答案合并到 PRD，自动读取已保存文件 |
| `/pg_plan` | 技术设计 | 生成程序设计文档，等待「开始产码」指令 |
| `/pg_task` | 任务拆分 | 将设计文档拆解为可执行子任务清单，含工时估算 |
| `/pg_code` | 开始产码 | 按任务清单逐文件产出代码，支持断点续传 |
| `/pg_fix` | 修改代码 | 输出修改方案等确认后执行，防止超范围改动 |
| `/pg_edit` | 修改文档 | 修改 PRD 或设计文档，自动归档新版本 |
| `/pg_review` | 代码审查 | 七维度 Code Review，输出 🔴/🟡/🟢 分级审查报告 |
| `/pg_test` | 测试用例 | 基于 PRD 验收标准生成功能/边界/异常三类用例，可交 QA |
| `/pg_ut` | 单元测试 | 基于产出代码生成 Java 单元测试（Mockito），逐任务产出 |
| `/pg_verify` | 验证 | 对照设计文档验证代码，输出 ✅/⚠️/❌ 报告 |
| `/pg_done` | 收尾 | 汇总产物、上线 Checklist、变更记录，标记需求完成 |
| `/pg_archive` | 归档 | 按需求分包归档，知识沉淀 + 失效检测，文件名自动加日期 |
| `/pg_recall` | 知识召回 | 根据当前任务从知识库检索相关业务知识，注入会话上下文 |
| `/pg_recap` | 知识萃取 | 扫描会话中的纠正/确认/实现事件，提炼并写入知识库 |
| `/pg_knowledge_clean` | 知识库维护 | 清理过期/重复/残缺的知识条目，维护知识库健康度 |
| `/pg_knowledge_init` | 知识库初始化 | 主动扫描代码库，逐维度萃取已有规则/约定/踩坑，批量写入知识库 |


### 完整流程图

```
[新/老项目统一] → /pg_knowledge_init → 初始化知识库（一次性建立长期记忆）
               ↓ 持续运行
           /pg_recap（每次会话后）→ 增量沉淀知识

[老旧项目] → /pg_analyze → 生成「现状设计文档」
                                    ↓
/pg_spec [需求名] → /pg_prd → /pg_clarify → /pg_plan
                                                   ↓（使用「现状设计文档」作为输入）
                                              /pg_task
                                                   ↓
                                   /pg_code ←──────┤
                                   /pg_fix  ←──────┤  开发阶段（可反复）
                                   /pg_edit ←──────┘
                                                   ↓
                                              /pg_verify
                                                   ↓
                                              /pg_done → /pg_archive
```

## 第一步：解析用户意图

识别用户输入属于以下哪种情况：

### 情况 A：初始化新需求
用户在 `/pg_spec` 后携带了需求名称或描述，如：
- `/pg_spec 商品一致性巡检新功能`

### 情况 B：查看当前状态
用户仅输入 `/pg_spec`，无其他内容

---

## 第二步A：初始化新需求

### 1. 推断项目根目录（按以下顺序依次尝试）

| 优先级 | 方法 | 条件 |
|---|---|---|
| 1 | 当前目录或其父目录存在 `.git` | 向上递归查找，找到即为项目根 |
| 2 | IDE 当前活跃工作区根目录 | 不需要 .git |
| 3 | 找不到（无 .git、无工作区） | **必须明确询问用户**，不得自行假设 |

**无法自动确定时，输出以下提示并等待用户确认：**

> ⚠️ 无法自动确定项目根目录（未找到 `.git` 且无工作区信息）。
>
> `pg/doc/` 应存放在项目目录内，请确认项目根目录：
>
> 1. 将当前目录作为项目根㄀目录路径将为 `[pwd]/pg/doc/`）
> 2. 手动指定路径：`/pg_spec 需求名 path:/绝对路径/`

### 2. 确认并展示路径

**在创建目录前，展示计划并等待用户确认（Markdown 格式，非代码块）：**

---

📋 **需求初始化确认**

需求名称：`[requirementName]`
项目根目录：`[project root path]`
Spec 存储目录：`[project root]/pg/doc/[requirementName]/`

这个项目根目录是否正确？
→ 回复「确认」开始初始化
→ 回复「修改 path:/绝对路径/」手动指定

---

### 3. 创建目录和状态文件

用户确认后：

1. 创建目录 `[project root]/pg/doc/[requirementName]/`
2. 写入 **`spec-status.json`**：

```json
{
  "requirementName": "[requirementName]",
  "projectRoot": "[project root]",
  "currentPhase": "待需求分析",
  "specDir": "[project root]/pg/doc/[requirementName]/",
  "files": {},
  "createdAt": "[当前ISO时间]",
  "updatedAt": "[当前ISO时间]"
}
```

3. 在回复中告知用户：

✅ **需求已初始化！**

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 需求：[requirementName]
📍 当前阶段：待需求分析
📁 Spec 目录：`[specDir]`
🧱 项目根：`[projectRoot]`
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

⏭️  下一步：`/pg_prd [需求来源]` 开始生成需求文档

支持的需求来源：
- Confluence 页面链接
- YAPI 接口链接
- 直接描述需求文字

若为老旧项目，建议先执行：`/pg_analyze` 梳理现有系统架构

---

## 第二步B：查看当前状态

1. **查找 `spec-status.json`**（按优先级扫描）：
   - 当前项目目录下的 `pg/doc/` 目录（递归查找各需求子目录中的 spec-status.json）
   - `~/pg/doc/` 目录
   - 若找到多个，展示最近修改的并询问用户确认

2. **若找到，输出状态面板**：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 需求：[requirementName]
📍 当前阶段：[currentPhase]
📁 文件目录：[specDir]
🕐 最后更新：[updatedAt]
📊 产码进度：[已完成文件数]/[总文件数]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📂 当前产物：
  [遍历 files 字段显示]

🛀 工作流进度：
  ✅ 已完成 / ⏳ 进行中 / ⬜ 待进行

  ⬜ /pg_analyze — 遗留系统梳理（老旧项目专用）
  ✅ /pg_prd     — 需求文档已生成
  ✅ /pg_clarify — 澄清已完成
  ⏳ /pg_plan    — 进行中
  ⬜ /pg_task    — 待任务拆分（含工时估算）
  ⬜ /pg_code    — 待产码
  ⬜ /pg_status  — 产码进度查询
  ⬜ /pg_fix     — 修改代码（按需）
  ⬜ /pg_edit    — 修改文档（按需）
  ⬜ /pg_review  — 待 Code Review（🔴/🟡/🟢 分级）
  ⬜ /pg_test    — 待生成测试用例（交 QA 执行）
  ⬜ /pg_verify  — 待开发自验（✅/⚠️/❌ 报告）
  ⬜ /pg_done    — 待收尾（含上线 Checklist）
  ⬜ /pg_archive — 归档产物

⏭️  建议下一步：`/pg_plan [补充说明]`
🔍 查看产码进度详情：`/pg_status`
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

3. **若未找到**：

```
⚠️ 未找到进行中的 PG Spec 工作流。

→ `/pg_spec [需求名称]` 初始化新需求
→ `/pg_analyze` 开始遗留系统梳理（老旧项目使用）
```
