description: PG - 开始产码命令 - 按任务清单逐文件产出代码，每文件等待确认，产码完成后引导 /pg_verify (PG Code Generation Command)
---

当用户**明确输入 `/pg_code` 命令**时，你必须严格按照以下步骤执行。

> ⚠️ **触发限制**：本命令只能由 `/pg_code` 触发。用户说「开始产码」「好的继续」「开始吧」等自然语言**不触发本命令**，应提示用户输入 `/pg_code`。

---

## 产码执行规范（整个产码过程中必须严格遵守）

### 范围锁定
- **只产出「涉及文件清单」中明确列出的文件**，不得额外新建
- 若需新增清单外的文件，必须先告知用户并等待确认

### 代码质量规范
- **注释**：所有注释使用简体中文，public 方法必须有 Javadoc 中文注释
- **Import**：禁用通配符 `*`，必须导入完整类名
- **命名**：严格遵循《已有系统程序设计文档》的命名规范
- **格式**：仅格式化修改的代码，不对未修改部分做格式调整

### 逐文件确认
- 默认每次只输出一个完整文件，等待用户确认后继续
- 用户输入 `/pg_code all` 可切换为全自动顺序产出

---

## 执行步骤

### 第一步：前置检查 + 断点恢复

读取 `spec-status.json` 进行以下检查：

```
✅ 前置检查：
□ 设计文档存在（files.design 指向的文件）
□ 任务清单存在（task.md）
□ 代码写入路径明确（有活跃工作区或用户已指定）
```

任何一项不满足则停止并告知用户需要先执行哪个命令。

**断点恢复**：若 `codeProgress.completedList` 不为空，展示恢复提示：

```
🔄 检测到上次产码进度：
   已完成 [N] 个文件：[文件列表]
   当前进度：[X]/[Total]

→ 输入「继续」从 [下一个文件] 继续产码
→ 输入「重新开始」从第一个文件重新产出
```

---

### 第二步：宣告产码计划

```
🚀 开始产码！

本次共需产出/修改 [N] 个文件：
| 序号 | 状态 | 操作 | 文件路径 | 说明 |
|---|---|---|---|---|
| 1 | ✅ 已完成 | 新增 | controller/XxxController.java | （已跳过）|
| 2 | ⏳ 进行中 | 新增 | service/XxxService.java | ... |
| 3 | ⬜ 待产出 | 新增 | mapper/XxxMapper.java | ... |

默认逐文件产出，每个文件完成后等待您确认。
输入 `/pg_code all` 可切换为全自动顺序产出。

开始产出第 [X] 个文件 → [文件名]
```

**立即**更新 `spec-status.json`：`currentPhase: "开发中"`，`codeProgress.currentFile` 设为当前文件。

---

### 第三步：逐文件产出代码

每个文件顶部附加说明注释：
```java
/**
 * [文件功能说明]
 * 对应设计文档章节：[章节引用]
 * 创建时间：[当前日期]
 */
```

产出完毕后展示确认菜单：

```
✅ [文件名] 已产出（第 [X]/[N] 个）

请检查代码，然后选择：
→ 输入「继续」产出下一个：[下一个文件名]
→ 输入「修改 [描述]」对当前文件提出修改（我会重新产出该文件）
→ 输入「有问题 [描述]」指出代码逻辑错误（我会分析并修正后重新产出）
→ 输入 `/pg_code all` 剩余文件全部自动产出
→ 输入 `/pg_code stop` 暂停并保存进度

⚠️ 注意：如果代码运行后发现 bug，请使用 `/pg_fix [描述]` 进行修复。
```

---

### 第四步：代码错误纠正引导

当用户对当前文件提出错误或修改时，按以下场景处理：

**场景 A：输出前发现逻辑问题（用户说「修改 [描述]」或「有问题 [描述]」）**
- 直接在当前文件重新产出，不进入下一个
- 重新产出后再次展示确认菜单
- 不计入 completedList，直到用户确认

**场景 B：代码运行后发现 bug（用户执行代码后反馈）**
```
💡 运行时 bug 建议使用 `/pg_fix` 处理：

→ `/pg_fix [bug描述]` — 输出定点修改方案，等待你确认后执行
（/pg_fix 会先展示 diff，不会直接修改文件）

当前产码进度已保存，修复完成后可继续 `/pg_code` 产出剩余文件。
```

---

### 第五步：打卡任务清单

每个文件产出被用户确认后，**立即**：
1. 在 `task.md` 中将对应子任务标记为 `[x]`
2. 更新 `spec-status.json` 的 `codeProgress`：
   - `completedFiles` +1
   - `completedList` 追加文件名
   - `currentFile` 设为下一个文件名

---

### 第六步：全部完成后

```
🎉 全部 [N] 个文件已产出完毕！

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 需求：[需求名称]
📍 当前阶段：验证中
⏭  建议下一步：`/pg_verify` 验证代码实现是否符合设计文档
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**立即**更新 `spec-status.json`：
- `currentPhase: "验证中"`
- `codeProgress.currentFile: null`
- `codeProgress.completedFiles: [总数]`

---

## 特殊指令

| 指令 | 行为 |
|---|---|
| `/pg_code all` | 剩余文件全部自动产出，不等待确认 |
| `/pg_code [文件名]` | 只产出指定文件 |
| `/pg_code skip` | 跳过当前文件，继续下一个（不计入完成） |
| `/pg_code stop` | 暂停产码，保存当前进度到 spec-status.json |

---

## 禁止行为

- ❌ 禁止通过自然语言（「开始产码」「好的」「继续」）触发本命令
- ❌ 禁止产出「涉及文件清单」以外的文件（需用户确认）
- ❌ 禁止一次性输出所有文件（除非用户明确输入 `/pg_code all`）
- ❌ 禁止英文注释
- ❌ 禁止自动执行 `git commit`
- ❌ 禁止在未更新 codeProgress 的情况下产出下一个文件
