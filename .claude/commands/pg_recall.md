---
description: PG - 知识召回命令 - 根据用户描述的任务，主动检索项目级 Knowledge Base 中相关知识并注入当前会话上下文，缩短 AI 冷启动时间（Knowledge Recall Command）
---

当用户输入 `/pg_recall` 命令时，你必须严格按照以下步骤执行：

---

## 前置：确定 Knowledge Base 路径

Knowledge Base 存储在**当前项目根目录**下的 `pg/knowledge/` 目录。

**项目根目录识别方式（按优先级依次尝试）**：
1. 当前工作区（Workspace）的根目录
2. 执行 `git rev-parse --show-toplevel` 获取 git 仓库根目录
3. 若均无法确定，询问用户：「请告知你的项目根目录路径」

**Knowledge Base 完整路径**：`{项目根目录}/pg/knowledge/`

---

## 第一步：要求用户描述当前任务

输出以下提示（不得添加任何其他内容）：

```
🔍 知识召回

请简述你当前要做的事情（1-2 句话，关键词越具体越好）：
```

等待用户输入。

---

## 第二步：读取 Knowledge Base 全量内容

逐一读取以下分类文件：

```
{项目根目录}/pg/knowledge/
├── business_terms.md     （📚 业务术语）
├── system_arch.md        （🏗️ 系统架构）
├── data_rules.md         （📊 数据规则）
├── platform_specs.md     （🌐 平台特性）
├── team_process.md       （⚙️ 团队约定）
└── domain_logic.md       （💡 业务逻辑）
```

若 `pg/knowledge/` 目录不存在或所有文件均为空，跳转至【空库处理】。

---

## 第三步：根据任务描述检索相关知识

基于用户输入的任务描述，从所有 KI 文件中匹配相关条目。

**匹配策略**（从高到低优先级）：
1. **直接关键词命中**：条目标题或定义中包含用户输入的关键词
2. **场景关联命中**：条目的"使用场景"与用户任务描述高度吻合
3. **分类关联命中**：用户任务属于某分类的典型场景（如任务涉及平台差异 → 自动包含 `platform_specs` 相关条目）

**相关性阈值**：只输出**明确相关**的条目，宁可少召回也不要召回噪声。

---

## 第四步：输出召回结果并注入上下文

### 情况 A：找到匹配知识

```
🔍 已为「[用户任务描述摘要]」召回以下相关知识：

📚 业务术语
  • [条目名称]：[定义原文]

🏗️ 系统架构
  • [条目名称]：[定义原文]

🌐 平台特性
  • [条目名称]：[定义原文]

---
✅ 以上知识已注入本次会话上下文。

现在请描述你的具体需求，我会基于以上背景知识为你工作。
```

> ⚠️ 召回结果输出完成后，你必须将以上所有召回知识作为本次会话的**隐性上下文前提**，在后续对话中默认已知这些信息，不再重复解释。

### 情况 B：未找到匹配知识

```
🔍 检索完成

未找到与「[用户任务描述摘要]」相关的已沉淀知识。

💡 建议：
  • 直接描述你的需求，遇到业务知识时按需解释给我
  • 本次会话结束后可用 /pg_recap 将新知识沉淀到 Knowledge Base

现在请描述你的具体需求。
```

### 空库处理（pg/knowledge/ 不存在或所有文件为空）

```
🔍 Knowledge Base 当前为空

当前项目尚未沉淀任何业务知识（{项目根目录}/pg/knowledge/ 不存在或为空）。

建议：
  • 直接开始描述你的需求
  • 会话结束后使用 /pg_recap 开始积累第一批知识

现在请描述你的具体需求。
```

---

## 禁止行为

- ❌ 禁止从项目目录以外的任何固定路径（如 ~/.gemini/antigravity/knowledge/）读取知识库
- ❌ 禁止在未读取 KI 文件的情况下输出召回结果（必须真实读取文件）
- ❌ 禁止为了"看起来有用"而过度召回无关条目（宁缺毋滥）
- ❌ 禁止在召回输出后要求用户再次确认（直接进入任务）
- ❌ 禁止跳过第一步直接检索（必须先获取用户任务描述）
