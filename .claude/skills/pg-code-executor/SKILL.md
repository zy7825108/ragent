# Pg Code Executor 产码执行规范技能

## 一、核心原则

1. **范围锁定**：只产出或修改「涉及文件清单」中明确列出的文件，不得额外新建
2. **逐文件确认**：默认每次只输出一个文件，等待用户确认后继续（可用 `/pg:code all` 切换全自动）
3. **先读后写**：产码前必须重新读取 `implementation_plan.md` 确认范围和规范
4. **遵守项目规则**：严格遵守全局 user rules 中的代码规范（注释、import、命名等）
5. **产码完成即提示验证**：所有文件产出完毕后，自动提示用户使用 `/pg:verify`

---

## 二、`/pg:code` — 开始产码执行步骤

### Step 1：前置检查
执行 `/pg:code` 时，首先检查以下项目：

```
✅ 前置检查清单：
□ implementation_plan.md 存在且已被用户确认（含「开始产码」指令）
□ task.md 存在且包含待执行的子任务清单
□ 当前工作区已确认（知道代码写到哪个项目目录）
```

若任何一项缺失，立即告知用户并停止，等待补充。

### Step 2：读取任务清单
从 `task.md` 中提取所有 `[ ]`（未完成）状态的子任务。
从 `implementation_plan.md` 中读取「涉及文件清单」，作为**产码范围边界**。

### Step 3：宣告产码计划
在开始产码前输出产码计划：

```
🚀 开始产码，本次共需产出 [N] 个文件：

| 序号 | 文件 | 操作 | 状态 |
|---|---|---|---|
| 1 | XxxController.java | 新增 | ⏳ 待产出 |
| 2 | XxxService.java | 新增 | ⏳ 待产出 |
| 3 | ApolloConfig.java | 修改 | ⏳ 待产出 |

默认逐文件产出，每个文件完成后等待您确认。
输入 `/pg:code all` 可切换为全自动顺序产出。
```

### Step 4：逐文件产出
- 每次只输出一个完整文件的代码
- 文件头部附加说明注释（文件用途、对应设计文档章节）
- 产出完毕后询问：

```
✅ 文件 [文件名] 已产出（[序号]/[总数]）

是否继续产出下一个文件？[XxxService.java]
- 输入"继续"或直接回车 → 继续下一个
- 输入"修改" → 对当前文件提出修改意见
- 输入"/code all" → 剩余文件全部自动产出
```

### Step 5：打卡任务清单
每个文件产出并被用户确认后，在 `task.md` 中将对应子任务标记为 `[x]`。

### Step 6：产码完成后提示
所有文件产出完毕后输出：

```
🎉 全部 [N] 个文件已产出完毕！

建议下一步：
→ 使用 `/pg:verify` 验证代码实现是否符合设计文档
→ 如有需要修改的地方，使用 `/pg:fix [描述]`
```

## 三、`/pg:fix` — 修改代码执行步骤

### Step 1：解析修改意图
从用户描述中提取：
- **问题类型**：Bug修复 / 需求变更 / 代码优化 / 重构
- **定位文件**：推断需要改动的文件（结合 `implementation_plan.md` 和代码上下文）
- **影响范围**：预估修改会影响的其他文件或模块

### Step 2：输出修改方案（必须等待确认）
在执行任何修改前，先输出受影响文件和修改方案：

```
📝 修改方案确认

【问题描述】：[用户描述]
【影响文件】：
  - XxxService.java — 修改 doSomething() 方法逻辑
  - ApolloConfig.java — 新增配置项 xxx.timeout

【修改范围说明】：
  仅修改以上 2 个文件，不涉及其他文件。

是否确认按此方案执行修改？(确认 / 取消 / 我要补充)
```

### Step 3：执行修改
用户确认后，逐文件输出修改后的完整代码（或 diff 格式）。

### Step 4：判断是否需要同步文档
修改完成后，判断本次改动是否影响到程序设计文档：
- 若涉及接口路径变更、字段变更、核心逻辑变更 → 提示使用 `/pg:edit` 同步文档
- 若仅为 Bug 修复、无接口/逻辑变化 → 无需同步文档

### Step 5：建议下一步

```
✅ 代码修改完成！

→ 如需同步更新程序设计文档：`/pg:edit 更新[章节名]中的[具体内容]`
→ 如需验证整体实现：`/pg:verify`
```

---

## 四、禁止行为

- ❌ 禁止在未获得用户确认的情况下修改「涉及文件清单」以外的文件
- ❌ 禁止一次性输出所有文件而不经过逐文件确认（除非用户明确输入 `/pg:code all`）
- ❌ 禁止在产码过程中自行修改 `implementation_plan.md` 的设计内容
- ❌ 禁止使用通配符 import，禁止英文注释（遵守全局规范）
- ❌ 禁止自动执行 `git commit`（遵守全局规范）
