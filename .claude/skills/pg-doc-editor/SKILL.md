# Doc Editor 文档编辑规范技能

## 一、核心原则

1. **保留结构**：修改文档时必须保留所有章节，不得删除任何章节标题（即使内容为空写"暂无"）
2. **版本可追溯**：每次修改自动更新文档头部的"版本"和"更新记录"字段
3. **范围最小化**：只修改用户指定的内容，不对无关章节做格式调整
4. **归档新版本**：修改完成后写入新版本文件，不覆盖历史文件
5. **输出完整文档**：始终输出完整的修改后文档，不得以"…其余不变…"省略

---

## 二、`/pg_edit` — 修改文档执行步骤

### Step 1：识别文档类型与修改意图

从用户输入中提取：
- **目标文档**：PRD / 程序设计文档 / 澄清记录 / 其他
- **修改内容**：用户具体描述要修改哪个章节、改什么
- **修改原因**：需求变更 / 信息补充 / 错误修正 / 代码变更同步

### Step 2：读取当前最新版本文档

1. 读取 `spec-status.json` 获取 `specDir` 和对应文档路径
2. 若 `spec-status.json` 不存在，要求用户提供文档路径或粘贴文档内容
3. 读取文件内容，确认当前版本号

### Step 3：输出修改预览（必须等待确认）

在执行写入前，输出修改内容的预览：

```
📝 文档修改预览

【目标文档】：PRD_商品一致性巡检_20260330.md（当前版本 v1.2）
【修改章节】：第 4 章 详细功能描述 - 4.1 触发条件
【修改内容】：
  原文：触发条件为用户手动点击"开始巡检"按钮
  修改为：触发条件为：1）用户手动点击"开始巡检"按钮；2）系统每日 00:00 自动触发定时巡检

【同时影响】：
  - 第 10 章 主流程图需同步更新（新增定时触发路径）

是否确认按此方案修改？(确认 / 取消 / 我要调整)
```

### Step 4：执行修改并更新版本信息

用户确认后，在文档头部的元信息中更新：

```markdown
---
归档时间: YYYY-MM-DD HH:mm      ← 更新为当前时间
需求名称: [需求名称]
文档类型: PRD
版本: v1.3                      ← 版本号 +1
更新记录:
  - v1.3 (2026-03-30): 修改第4章触发条件，补充定时触发场景
  - v1.2 (2026-03-29): 合并澄清答案，补充边界限制
  - v1.0 (2026-03-28): 初版生成
---
```

### Step 5：写入新版本文件

- **新文件命名规则**：
  - 同一天：`PRD_[需求名]_YYYYMMDD_v2.md`（追加版本号）
  - 不同天：`PRD_[需求名]_YYYYMMDD.md`（更新日期）
- 不删除旧版本文件
- 更新 `spec-status.json` 的 `files.prd`（或 `files.design`）指向最新版本

### Step 6：告知完成并建议下一步

```
✅ 文档已更新至 v1.3！

【新版本路径】：[文件路径]
【修改摘要】：修改第4章触发条件，补充定时触发场景

建议下一步：
→ 如有关联代码需同步修改：`/pg_fix [描述]`
→ 如需继续验证：`/pg_verify`
→ 如修改完毕准备收尾：`/pg_done`
```

---

## 三、文档修改后的关联检查

修改完成后，自动检查本次修改是否影响其他文档或代码：

| 修改类型 | 需要同步的地方 |
|---|---|
| 接口字段变更（PRD 第6章） | 程序设计文档第5章（API设计）|
| 业务流程变更（PRD 第4章） | PRD 第10章（流程图）、程序设计文档第7/8章（时序图/流程图）|
| 边界条件变更（PRD 第5章） | 程序设计文档第11章（风险点）|
| 程序设计文档中接口变更 | 代码中对应的 Controller/VO |

若检测到需要同步，提示用户：

```
⚠️ 关联同步提醒

本次修改可能影响以下内容，建议同步处理：
- 程序设计文档第5章接口设计（与PRD字段修改一致）→ `/pg_edit 更新程序设计文档第5章`
- 对应代码中的 XxxVO.java → `/pg_fix 同步修改 XxxVO 字段`
```

---

## 四、禁止行为

- ❌ 禁止删除任何章节标题（即使内容为空）
- ❌ 禁止对未指定修改的章节做格式调整（避免无意义 diff）
- ❌ 禁止以"…其余内容不变…"省略输出，必须输出完整文档
- ❌ 禁止覆盖历史版本文件（新版本存新文件）
- ❌ 禁止未经确认直接写入文件
